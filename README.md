# A 股资金流动大盘

每天收盘后，用一张图回答一个问题：**钱在往哪流？**

不预测点位，不给买卖建议，只把「资金流向的事实」摆清楚，并做规则化判读。

```bash
python3 main.py --open     # 拉今日数据 → 终端摘要 + HTML
```

零第三方依赖，纯 Python 标准库，Python 3.9+。

---

## 它回答什么

| 问题 | 面板 |
|---|---|
| 今天大盘是进攻还是防守？ | 市场状态（四态）+ 大盘脉搏 |
| 钱流进哪些板块？流了几天了？ | **板块轮动四象限**（核心） |
| 单日流入是真信号还是诱多？ | 背离警报：今日流入但中期流出 |
| 情绪过热还是冰点？ | 涨停/跌停、封板率、连板梯队、两融 |
| 外盘什么风向？ | 美股/港股/日经/美元/离岸人民币 |

## 板块资金热力图（treemap）

除了四象限散点，还有一张**面积=成交额、颜色=主力净额方向**的热力图：

- **面积编码规模**：成交额越大的板块占面积越大，一眼看出钱集中在哪
- **颜色编码方向**：红=主力净流入、绿=净流出，深浅表示强度
- **全部绘制，不按面积截断**：457 个板块 100% 覆盖，小到 2px 的块不写字但**仍在图中**
- 色阶**自适应**：用当天截面 |净额/成交额| 的 90 分位作量程，避免"全市场普跌日"整屏一片绿

两张图互补：散点看**分布形态**（谁在哪个象限），热力图看**绝对规模**（钱堆在哪）。

## 核心：四象限轮动矩阵

把 496 个行业 + 531 个概念板块，按 **今日主力净额** 和 **近5日主力净额** 两个维度放进四个象限：

```
                    今日净流入 ↑
                         │
     ④ 拉高出货          │          ① 流入加速
   （中期流入，今日流出） │    （今日+中期同向流入）
   ←─────────────────────┼─────────────────────→
     ③ 持续失血          │          ② 抄底试探
   （今日中期双流出）     │    （今日流入，中期仍流出）
                         ↓ 今日净流出
```

**最有用的是 ②「抄底试探」和 ④「拉高出货」这两个背离象限**——它们才是资金流指标真正的价值所在。
单看"今日流入榜"会系统性被骗：拉高出货的板块当天也可能净流入。

### 实测样本（2026-11-03）

- 电力设备：今日主力 **+34.3 亿**（全行业第一），但 5 日 **−34.3 亿**、10 日 **−201.7 亿**
- 典型「抄底试探」：单日资金掉头，中期仍在失血。这类信号需要后续几日确认，不能单日追。

## 资金强度分

对每个板块计算 0–100 分：

```
原始分 = 0.5 × rank(今日净额) + 0.3 × rank(5日净额) + 0.2 × rank(10日净额)
调整   = 一致性加分 / 背离扣分
```

同时输出 **净额 ÷ 流通市值** 作为归一化强度——否则 5000 亿的大板块永远排在 50 亿小板块前面，
而真正推动股价的是"流入占自己体量的比例"。

## 数据来源与真实性约束

数据来自东方财富公开接口（免 Key）。**这一节是这个项目最重要的部分。**

### 已验证的字段语义

`f164` = 近5日累计、`f174` = 近10日累计，这两个是本项目从接口"猜"出来的字段，
因此**用日线逐日累加做了独立交叉验证**（见 `selftest.py` 第 1 节），误差 < 1%。
不验证就用的字段，等于把结论建在猜测上。

### 明确不做的字段

| 字段 | 原因 |
|---|---|
| **北向资金每日净流入** | 2024-08 起交易所**已停止披露**。接口返回 `status:3, dayNetAmtIn:0`。市面上大量"北向资金大盘"是拿南向数据或模型估算冒充的。本项目**不显示、不估算、不用南向冒充**。 |

### 已知口径说明

- **主力资金** = 东财按单笔成交金额分档（超大单/大单）的**估算**，不是真实席位数据。是相对指标，不是绝对真相。
- **两融是 T+1**：今天看到的是昨天数据，面板会标注实际日期。
- **涨跌停数以交易所涨停/跌停板池为准**，不用 ±9.8% 阈值——创业板/科创板是 20% 限制，简单阈值会把 48 家涨停算成 59 家、17 家跌停算成 93 家。
- **成交额双口径校验**：指数成交额合计 vs 个股成交额合计，偏差 > 5% 会在 `selftest` 报警。

### 自洽性验证

每次运行都会检查：
- 涨 + 跌 + 平 == 有效个股数
- 指数成交额合计 ≈ 个股成交额合计（实测偏差 0.68%）
- 板块净额量级合理

## 文件结构

```
market-flow/
├── CONTRACT.md          # 数据契约（字段语义、接口清单、模块边界）—— 改代码前先读
├── fetch.py             # 取数：8 线程并发，全市场 5927 只 + 1027 板块，约 2.3 秒
├── store.py             # 存储：完整快照 + flows.jsonl 轻量时序（为将来回测留口子）
├── metrics.py           # 计算：打分 / 四象限 / 情绪 / regime / 规则判读（纯函数，无 IO）
├── render_html.py       # 渲染：自包含 HTML，内嵌 SVG，零 CDN（纯函数，无网络）
├── render_term.py       # 渲染：终端 ANSI 摘要（纯函数）
├── main.py              # 编排 + CLI
├── selftest.py          # 端到端测试 46 项，测真实数据路径（含回归断言）
└── data/
    ├── YYYY-MM-DD.json  # 完整快照
```

**架构约束**：`metrics.py` 和 `render_*.py` 是纯函数，不碰网络也不碰磁盘。

## 要每日执行吗？

**答案分层，不是简单的"要"或"不要"。**

```bash
python3 daily.py          # 判断现在该不该跑
python3 daily.py --check  # 只看状态
```

| 时段 | 要跑吗 | 原因 |
|---|---|---|
| **收盘后 15:15 之后** | ✅ **要** | 唯一能积累完整历史的窗口，数据已定盘 |
| 盘中 / 午间休市 | △ 可跑，**不落盘** | 拿到的是半日数据；程序自动拒绝落盘 |
| 盘前 / 集合竞价 | ❌ 不要 | 接口返回占位符，跑出来是空盘 |
| 周末 | ❌ 不要 | 无新行情，重复跑只覆盖同一份数据 |

### 漏跑了怎么办

| 数据类型 | 能补吗 | 说明 |
|---|---|---|
| **板块级**（净额/收盘价/涨跌幅） | ✅ 能补 **120 个交易日** | `python3 backfill.py --days 30`，496 板块并发约 8 秒 |
| **个股级截面**（涨跌家数/个股榜/涨停池/两融快照） | ❌ **永久丢失** | 接口只给"单标的序列"，不给"某日全市场截面" |

**所以准确的说法是**：每天收盘后跑一次就够了，但**不是必须**。
真正会因漏跑而永久丢失的，只有"当日全市场宽度指标"这一类截面数据。

实测已验证：`backfill.py --days 30` → 回补 29 天，10-20/10-30/11-03 抽查 9/9 板块净额与日线真值**误差 0.0000 亿**。

### 盘中运行的安全保护

实测踩过的坑：盘中运行会用旧日期把当日半日数据写入归档，**覆盖已保存的收盘值**
（11-03 成交额 17151 亿 → 被覆盖成 8709 亿，不可逆）。

已三层修复：
1. `fetch.py` 的 `as_of` 改为**优先本地日期**，不再用滞后的日线推断值
2. `store.save()` **盘中拒绝落盘**（按 09:30-11:30 / 13:00-15:00 时间窗判定）
3. `selftest.py` 新增断言：归档快照的 `generated_at` 不得晚于 `as_of`（回补/修复快照豁免）

## 开发过程中实测发现并修掉的坑

这一节记录的都是**真实数据验证出来的问题**，不是理论推演：

| 坑 | 现象 | 修法 |
|---|---|---|
| 指数代码键不匹配 | `indices` 恒为空，只报"不可用" | 接口返回 `"000001"` 而 `INDICES` 用 `"1.000001"`，改以纯代码为键 |
| 跌停池有总数无明细 | `tc=17` 但 `pool=[]` | `sort=fbt:asc` 是涨停板专用排序键，跌停池须用 `fund:asc` |
| 涨跌停数被高估 | 48 家涨停被算成 59、17 家跌停算成 93 | 创业板/科创板是 20%、北交所 30%，改用交易所池为准 |
| 打分饱和 | 12 个板块并列 100 分、36 个并列 0 分 | 截面 min-max 单调重标定，相对次序不变 |
| 申万Ⅱ/Ⅲ重复条目 | TOP20 被同义孪生条目挤占 | 三项净额相同即判同族，按Ⅱ<Ⅲ<Ⅳ保留更高级分类 |
| 象限容器键不匹配 | 终端绕过上游去重，重复项重现 | `{"count","rows"}` 的 `rows` 未被渲染层识别，两端口径归一 |
| 同指标两视图数字不一致 | 终端 38.9% vs HTML 37.8% | 分母口径不同（是否含平盘），统一取 metrics 的 `up_ratio` |
| CFF 字段名泄漏到界面 | 显示"个股 f62 合计""个股 f6 合计" | 换成"全部 A 股主力净额加总"等通俗表述 |
| 模板 `<br>` 被整体转义 | 页面显示出字面量 `<br>` | 静态排版标记与动态数据分开转义 |
| 背离列表噪声 | 73 条全列，"另有 70 个"等于没警报 | 三层：全量73 / 过门槛16 / 展示TOP5，按"裂口×sqrt(规模)"排序 |
| CJK 歧义宽度错位 | 含 Ⅱ/Ⅲ 的 82 个板块名整行左缩 1 列 | `East_Asian_Width='A'` 在中日韩终端按 2 列计 |
| 成交额环比 | 首次运行无历史 | 从 `flows.jsonl` 读前一日，取不到如实降级为 None |
| **盘前空盘被当成真实数据** | 盘前全市场 `f62` 全返回 `"-"`，会被算成"涨0跌0、上证0.00%"，看着像暴跌 | 取数层识别 `trading_state=pre_market_or_closed`，metrics **短路拒绝产出当日结论**，渲染层置顶警告横幅 |
| **滚动窗口对齐点漂移** | 盘前 `f164` 等于日线末**4**根之和（窗口含当日空值），而非末5根 | 断言识别"含当日"对齐方式，按末4/末9根验证，语义仍然正确 |
| treemap 按面积截断 | 只画成交额前 202 个板块，丢掉 255 个中小板块 | 全画 457 个，100% 覆盖，靠字号解决可读性 |
| 两融字段名 | 余额显示"—" | render 取 `margin_balance` 而非 `balance` |

## 预注册验证结果（2026-11-04，120 个交易日）

**方法**：先写 `PREREGISTRATION.md` 锁定假设、样本、基准与判定阈值，**再跑**。
目的：防止"看到结果后才决定怎么解释"。

**样本**：496 板块 × 110 交易日 = **54,560 个信号样本**（2026-05-25 ~ 11-03）
**基准**：全市场板块等权均值（锁定，不可换）
**通过条件**：|t|≥2.0 + 中位数与均值同号 + 分段符号一致 + n≥200，**五项全满足才算通过**

| 象限 | 均值 | t | 中位数 | 分段 | 判定 |
|---|---|---|---|---|---|
| 流入加速 | +0.15% | **+3.39** | **-0.10%** | +/+/+ | ❌ 中位数与均值反号 |
| 抄底试探 | -0.03% | -0.66 | -0.21% | -/-/**+** | ❌ t不显著、分段翻转 |
| 持续失血 | -0.05% | **-2.23** | -0.22% | -/-/**+** | ❌ 第三段翻正 |
| 拉高出货 | +0.06% | +1.20 | -0.14% | +/+/**-** | ❌ 三项不满足 |

**0/4 通过。**

### 四个附加检验，逐个否掉

| 检验 | 结果 |
|---|---|
| **多重检验** | 未校正 12/16 显著；Bonferroni（|t|≥2.73）后**只剩 3/16** |
| **反转控制** | 剔除区间效应后，5 个区间仅 **1/5** 显著，多重检验后临界 |
| **随机标签** | 真实 t=-0.66 落在随机分布**第 20 百分位** → 仍是噪声 |
| **逐板块** | 流入加速 **51%** 板块为正、抄底试探 **49%** → 完全随机水平 |

### 又一次踩到"基准幻觉"，这次当场抓住了

初版 4.2 节显示"强组显著为正 t=5.79"，看似说明控制反转后仍有增量。
核查发现：**它用全市场均值作基准，而该区间整体就跑赢全市场（+0.224%）**。
强组 +0.350% 相对全市场显著，但相对**区间内均值**仅 +0.126pp。

这是"基准幻觉"的**第二个变体**——把区间效应误认为信号。
已作废该判定，用区间内中性化重做，结论翻开：1/5 显著。

**同一类错误在两周内犯了两次，说明"选对基准"比"算对数字"难得多。**

### 经济意义

所有 |均值| < 0.16%（5日），**未扣交易成本**。按双边 0.1% 计，净收益接近 0 或为负。
即使统计显著，也无经济意义。

## 早期信号验证结果（80 交易日，已被上面的预注册结果取代）

**结论对本项目不利，但必须留下来。**

用 496 个行业板块 × 80 个交易日 = **39,680 个信号样本**，检验四象限信号的预测力
（结果变量 = 板块未来收益 - 当日全市场板块均值，即 market-neutral 超额）。

| 检验 | 结果 | 判定 |
|---|---|---|
| 流入加速 5日超额 | +0.10%，t=+2.08，但**中位数 -0.11%** | 均值被极端样本拉动，不可用 |
| 抄底试探 分段稳定性 | 三段超额 -0.04% / +0.06% / -0.08% | **符号翻转**，不稳定 |
| 信号强度分层 | 强流入前10%：5日 -0.36%(t=-4.87)；强流出前10%：**-1.00%**(t=-12.76) | **越强越差**，排序本身是错的 |
| 控制短期反转后 | 资金流不再提供增量信息 | 无 alpha 贡献 |

**真正的规律是短期反转，与资金流无关：**

```
前5日涨幅 -1.6% ~ +0.5%  → 后5日超额 +0.41% (t=+10.52)  ← 最强
前5日涨幅 +3.1% ~ +50%   → 后5日超额 -0.32% (t=-7.12)   ← 回落
前5日跌幅 >3%            → 后5日超额 -0.51% (t=-9.16)   ← 继续跌
```

即「温和波动后反弹、强势上涨后回落」。试图用资金流增强这个信号**无效**：
前5日小跌 + 净流入最强10% → +0.20%（t=+1.63，不显著）。

**最重要的方法论教训：基准能伪造 alpha。**

开发中一度看到「抄底试探」5日超额 **+0.25%、t=+2.33**，看起来是显著正收益。
真相：那个结果来自 `validate.py --top 100` —— 它把样本宇宙缩到 100 个大板块，
**基准也只在 100 个板块内计算**。同一信号换回全市场基准后变成 **-0.15%（t=-1.31）**。

同一批样本、只换基准定义，结论从「显著正」翻成「不显著负」。
再固定全市场基准、按规模分组验证，各组并无系统性规律
（前50大 -0.37% / 50-100 +0.16% / 300名后 +0.19%），
证明不是"大板块更有效"，纯粹是**基准被换掉了**。

**教训：任何"显著"结论，都必须先问一句"基准是什么"。**
回测里最容易被无意识操纵的就是基准，而你通常不会觉得自己在作弊。

**另一个教训**：s
推翻它的是**中位数检验**（均值正/中位负）和**分层检验**（强度与收益负相关）。
只看均值显著性会自欺。

**因此定位不变**：这是「资金分布的**可视化**仪表盘」，不是交易信号系统。
资金流是有效的**同期描述**工具（当日净流入与当日涨跌 r=+0.29），
适合回答"今天为什么涨"，不适合回答"明天会怎样"。

样本仅 80 个交易日、单一市场环境（2026-07~11），**不足以确认也不足以否定**。
要在资金流上继续找 alpha，需要：更长历史（跨牛熊）、个股级口径、
控制已知因子后看增量、扣除交易成本与涨跌停约束。

```bash
python3 validate.py --days 90        # 完整回测（496 板块，约 6 秒）
python3 robustness.py               # 四项稳健性检验
python3 validate_summary.py          # 结论摘要
```

## 怎么确保信息是可信的

这是本项目最该被问的问题。答案分三层，每一层都有实际证据支撑（或明确说明证据缺失）。

### 第一层：数据被**正确读取**了吗？——有证据

| 手段 | 做什么 | 实测结果 |
|---|---|---|
| **字段语义交叉验证** | 用日线逐日累加验证 `f164`=5日、`f174`=10日 | 吻合到小数点后两位 |
| **独立供应商交叉** | 东财 vs 腾讯 vs 新浪，比指数点位与涨跌幅 | 价差 **0.000%**，6/6 一致 |
| **跨口径自洽** | 指数成交额合计 vs 个股成交额加总 | 偏差 **0.3~0.7%**（<5% 阈值） |
| **逻辑不变量** | 涨停≤总数、涨跌平=有效数 等 6 条硬约束 | 全部满足 |

这三条共同回答：**我们没有把接口的列读错，数字确实是它说的那个意思。**

### 第二层：数据**异常时**会不会被当成正常？——用变异测试验证

不只写断言，而是**故意注入错误，看防线是否真的抓住**：

| 注入的故障 | 修前表现 | 修后 |
|---|---|---|
| 所有板块净额置 0（接口坏掉典型形态） | 仍输出 1 个板块排名，无警告 | **拒绝产出排名** + 【数据退化】警告 |
| 涨幅全为 `-`（盘前） | 算成"涨0跌0"，看着像暴跌 | **识别为空盘**，拒绝当日结论 + 警告横幅 |
| 涨停数 = 个股总数 | 无反应 | **违反不变量**，明确报出 |
| 盘中窗口漂移 | 误报字段语义错误 | 识别盘中状态，跳过绝对值比对 |

**变异测试的价值**：它证明这道防线是**真的**，而不只是"写了断言"。

### 第三层：**上游口径本身**对不对？——无法自证，只能标注

这是最诚实的一段：**本项目对此没有防御能力。**

- 主力资金是东财按单笔金额分档的**独有估算口径**，没有第二家可比，无法交叉验证
- 单一数据源 → 如果东财口径本身有偏差，项目**永远发现不了**
- 北向资金已停止披露、研报覆盖等 4 类接口不可得 → 一律标注"不可得"，不估算

### 第四层：信号**能预测未来**吗？——已被证伪

见上方「信号验证结果」。资金流是有效的**同期描述**工具，不是预测工具。

### 一句话结论

```
「数据读对了」   → 有证据（三源一致，误差 <0.01%）
「异常能识别」   → 有证据（变异测试验证）
「口径本身合理」 → 无证据，只能标注（单一供应商）
「能预测收益」   → 已被证伪
```

```bash
python3 audit.py         # 9 个置信度维度逐项审计
python3 crosscheck.py    # 独立供应商交叉验证（东财 vs 腾讯/新浪）
```

**注意：`audit.py` 得分再高也不代表数据可信**——那是"防御性得分"，衡量的是"我们能想到的坑有没有堵上"。自己给自己打分永远可疑，所以可信度的硬证据来自 `crosscheck.py` 的**外部源**，而不是本项目内部的断言。

## 局限（必须知道）

- **资金流是滞后与估算指标**，不能预测未来。它描述"已经发生的钱的方向"。
- 单日数据噪声很大，**至少看 5 日**。本项目的价值在于把 5 日/10 日摆在单日旁边。
- 主力资金口径下，"净流入"不等于"股价会涨"——大单可能是拆单、对冲或被动指数调仓。
- 板块成分股是动态的，历史序列的板块口径与今天不完全可比。
- 没有基本面、估值、政策、事件维度。**这个大盘只管资金面，不能单独作为决策依据。**
